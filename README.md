# BimSAgent

Консольный AI-помощник по Autodesk Revit, BIM, Revit API, C#-плагинам и Dynamo.
Требуется .NET 10 SDK. Сторонних пакетов нет.

Из родительской папки:

```powershell
dotnet build .\BimSAgent\BimSAgent.csproj
dotnet run --project .\BimSAgent\BimSAgent.csproj
```

Перед запросом задайте `OPENAI_API_KEY` в окружении процесса через безопасный
механизм вашей среды. Приложение не запрашивает ключ в CLI, не сохраняет его
в файлы и не выводит в журнал. Сборка не требует ключа и не обращается к API.

Модель — `gpt-4.1-nano` (зафиксирована в коде, `OPENAI_MODEL` не используется).
Введите запрос одной строкой; `/exit`, Ctrl+C или конец ввода завершают работу.
Команда `generate-prompt` запрашивает задачу, затем лимит токенов ответа (целое число
от 16 до 32768) и создаёт один технический
prompt для её дальнейшего решения, без самого решения. Инструкции этого режима требуют
использовать только реальные возможности Autodesk Revit 2024 и Revit API 2024,
не выдумывать API и явно указывать отсутствие прямого способа, если его нет.
Задача с пометкой команды и созданный prompt сохраняются в обычной истории.
После prompt выводится стандартная статистика токенов; счётчик текущего запроса
включает пометку команды. Пустая задача отменяет команду без вызова API.
Память загружается из текущей рабочей папки при запуске. В `history.json` остаются
последние 3 сообщения (отдельные реплики пользователя или ассистента, не пары).
Более старые сообщения сжимаются через LLM в `summary-1.json`, `summary-2.json` и т.д.
Группы идут в хронологическом порядке, по 5 сообщений; остаток относится к самой
старой группе. Например, 15 исходных сообщений дают группы 2, 5, 5 и последние 3 без сжатия.
Существующая длинная история обрабатывается при запуске, до ввода команд.
После каждого успешного ответа применяется то же правило; даже группа из 1–4
сообщений получает новую сводку. Уже созданные сводки повторно не сжимаются.
В запрос передаются все сводки в числовом порядке, последние сообщения и новый запрос.
Для продолжения диалога запускайте программу из той же папки.
Сводки содержат текст, номер, число исходных сообщений и API-счётчики токенов сжатия.
При сбое сжатия исходные файлы не сокращаются. Для согласованной записи нескольких
файлов используется `memory-pending.json`: прерванная запись завершается при следующем
запуске без повторного вызова LLM. Не запускайте несколько экземпляров с одной папкой памяти.
Если файла нет, начинается новый диалог; файл создаётся после первого успешного ответа.
Повреждённая или недоступная история вызывает сообщение об ошибке и не перезаписывается.
При ошибке API новый обмен не сохраняется. Очень большое число сводок всё ещё
может превысить контекстное окно модели: автоматического усечения запроса нет.
Агент консультирует и генерирует текст, но не подключается к Revit.

Используется [OpenAI Responses API](https://developers.openai.com/api/reference/resources/responses/methods/create),
с инструкциями роли в `instructions` и запросом в `input`.

После ответа выводятся токены текущего сообщения и предыдущей истории
 (всех сводок и последних сообщений, переданных для этого ответа)
(отдельные вызовы `/v1/responses/input_tokens`, включая служебное оформление сообщений,
без инструкций роли). Для пустой истории выводится 0. Эти независимые счётчики
не следует складывать: каждый включает оформление отдельного входа.
Общий фактический вход с инструкциями и размер ответа берутся из `usage.input_tokens`
и `usage.output_tokens`. Если счётчик недоступен, выводится «недоступно», без оценки LLM.

Команда `context-limit-test` создаёт синтетический контекст и корректирует его размер
по счётчику API до ровно 1 050 000 входных токенов, включая инструкции и оформление.
Затем отправляет его с `truncation: disabled` и выводит ошибку `context_length_exceeded`.
Другие ошибки (например, HTTP 429) не считаются подтверждением переполнения.
Если подтвердить размер через API не удалось, генерация не запускается.
Тест не использует и не изменяет историю диалога. Команда выполняет реальные API-запросы
только при ручном вводе; сборка её не запускает.

Справка: [подсчёт входных токенов](https://developers.openai.com/api/reference/typescript/resources/responses/subresources/input_tokens),
[лимиты GPT-4.1 nano](https://developers.openai.com/api/docs/models/gpt-4.1-nano).
